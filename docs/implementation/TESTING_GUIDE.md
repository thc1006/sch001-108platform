# Gemini API 修復測試指南

> **版本：** v1.0
> **測試日期：** 2025-11-23
> **測試範圍：** Puter.js Gemini 3 Pro API 整合

---

## 測試目標

驗證所有7個使用 Puter.js AI 功能的頁面在升級至 `gemini-3-pro-preview` 模型後能正常運作。

---

## 測試前準備

### 環境需求
- **瀏覽器：** Chrome/Firefox/Edge（最新版本）
- **網路連線：** 穩定的網路連線（Puter.js需要連線到雲端服務）
- **開發工具：** 瀏覽器的 DevTools（用於檢查 Console 和 Network）

### 測試原則
遵循 **TDD (Test-Driven Development)** 原則：
1. **Red** - 確認問題存在（舊模型無法運作）
2. **Green** - 修復後功能正常運作
3. **Refactor** - 確保代碼品質和可讀性

## 錯誤處理測試

### 測試場景
1. **無網路連線**
   - 預期：顯示友善錯誤訊息「請檢查網路連線」

2. **空輸入**
   - 預期：顯示提示「請輸入內容」

3. **超長輸入**（>1000字）
   - 預期：正常處理或提示字數限制

4. **特殊字元輸入**
   - 輸入：`<script>alert('test')</script>`
   - 預期：正確轉義，不執行腳本

5. **快速連續點擊**
   - 預期：防抖處理，避免重複請求

## 已知限制

### Gemini 3 Pro 特性
1. **回應時間：** 相較於 Flash 模型略慢，但品質更好
2. **配額限制：** 若 Puter.js 有使用限制，可能需要降級方案
3. **回應格式：** JSON 格式可能不完全一致，已有容錯處理

### 瀏覽器相容性
- IE11 不支援（專案已不考慮支援）
- Safari < 14 可能有相容性問題

## 問題回報流程

### 發現問題時
1. **記錄完整資訊**
   - 瀏覽器版本
   - Console 錯誤訊息截圖
   - Network tab 請求/回應截圖
   - 重現步驟

2. **嘗試重現**
   - 至少重試3次確認問題穩定存在
   - 嘗試不同瀏覽器確認是否普遍問題

3. **建立 Issue**
   - 在 GitHub Issues 建立新問題
   - 使用標籤：`bug`, `AI`, `gemini-api`
   - 附上所有記錄資訊
