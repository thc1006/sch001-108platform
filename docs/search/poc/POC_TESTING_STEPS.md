# 🚀 FlexSearch POC 測試執行指南

> **目標**: 在 10 分鐘內完成核心測試，驗證 FlexSearch 可行性

---

## 📋 測試前準備

### 1️⃣ 開啟測試頁面

```bash
# Windows
start poc-flexsearch.html

# macOS
open poc-flexsearch.html

# Linux
xdg-open poc-flexsearch.html
```

### 2️⃣ 等待索引建立

觀察頁面上方「索引狀態」區塊：

```
🔵 準備中... → 正在載入（等待 1-2 秒）
🟢 ✅ 已就緒  → 可以開始測試 ✅
```

如果顯示 `❌ 載入失敗`，請檢查：
- `search-index.js` 檔案是否存在
- 瀏覽器控制台是否有錯誤訊息

## ⚡ 5 分鐘快速測試

### 🔥 測試 1: 中文部分詞搜尋（最重要！）

**步驟**:
1. 點擊快速測試區的 **「科學」** 按鈕
2. 觀察左右兩側的搜尋結果

**期望結果**:
- ✅ **FlexSearch（左側）**: 能找到「科學展覽」、「科學研究」等包含「科學」的詞
- ❌ **Fuse.js（右側）**: 可能只找到完全匹配「科學」的結果，或模糊匹配但準確度較低

**記錄到 POC_TEST_RESULTS.md**:
```markdown
## 測試案例 1: 中文部分詞搜尋

FlexSearch 結果數量: _____ 筆
Fuse.js 結果數量: _____ 筆
FlexSearch 是否匹配「科學展覽」: ☑ 是 ☐ 否
```

**這是 FlexSearch 的核心優勢！如果這個測試失敗，代表中文分詞有問題。**

## 🆘 常見問題

### Q1: 索引一直顯示「準備中...」

**解決方法**:
1. 檢查 `search-index.js` 是否存在
2. 開啟瀏覽器開發者工具（F12）查看 Console 錯誤
3. 確認網路請求是否成功（Network 分頁）

### Q2: 搜尋結果完全空白

**解決方法**:
1. 檢查搜尋索引是否正確載入
2. 確認輸入的查詢詞在索引資料中存在
3. 查看 Console 是否有 JavaScript 錯誤

### Q3: 速度沒有明顯差異

**可能原因**:
- 搜尋索引資料量太小（< 50 筆）
- FlexSearch 在小資料集下優勢不明顯
- 需要等到資料量 > 500 筆時才會有顯著差異
