資訊學群的多元表現，有一套不成文的「隱藏課程」：版本控制、技術寫作、社群參與、自主專案管理——這些都是軟體工程師的專業日常。大學正用多元表現這個機制，篩選那些已經開始實踐這些專業技能的學生。這一頁帶你規劃真正能加分的亮點。

## 競賽地圖：APCS 與其他

**APCS（大學程式設計先修檢測）** 是資訊類最重要的檢定。需釐清三件事：

- **2025 年改制**：原「程式設計觀念題」更名為「程式識讀」（可選 C 或 Python 題本），原「程式設計實作題」更名為「程式實作」（分初級/中級/中高級/高級四種題本）。全年檢測場次由 3 次增為 6 次（10、11、1、3、6、7 月），維持 1～5 級分制。
- **它是門檻，不是門票**：115 學年度多數校系 APCS 組要求「程式識讀＋程式實作各 4 級分」作為**檢定標準/報名門檻**，而非錄取保證。115 學年度採計 APCS 的資訊類組別已擴增至約 60 餘校系、約 218 個名額。
- **高分需要專案佐證**：APCS 證明你會「寫」程式，但作品集才能證明你會用程式「思考」。一份高分成績單若沒有對應的專案實作體現問題解決脈絡，說服力會大打折扣。在 AI 已能代寫程式碼的 2026 年，這項區別比以往更關鍵。

其他競賽：資訊、數學、自然科學領域的國內外競賽成績，是陽明交大等校明確參採的項目；科展（尤其能展現團隊分工與數據分析者）、黑客松同樣有價值。**競賽的價值不在名次本身，而在你能否反思策略、從失敗中學到教訓、剖析獲勝者的解法。**

## 作品集核心：GitHub 已是標配

對志在頂尖資工系的申請者，提供 GitHub 儲存庫連結已是**非選項，而是標配**；成大資工更在官方指引中強制要求。GitHub 對教授而言不只是雲端硬碟，而是能窺見你**思考過程**的窗口——commit 紀錄就是專案開發的日誌，忠實記錄你如何克服困難、逐步完善。一份優質的高中生 GitHub 儲存庫應具備：

1. **清晰的 README.md** — 說明專案動機（要解決什麼問題）、功能、安裝方式、過程中遇到的關鍵挑戰與學習。
2. **有意義的 commit 歷史** — 小而規律、訊息清晰（如 `feat: add user login`、`fix: resolve image loading bug`），講述持續努力的故事；避免一次性上傳所有檔案。
3. **可讀、附註解的程式碼** — 在複雜邏輯旁解釋「為何」這樣寫，而非只是「寫了什麼」。
4. **LICENSE 授權文件** — 如 MIT License，表明對智慧財產權的基本認知。
5. **docs/report 資料夾或 Issues 追蹤** — 附一份反思總結報告；用 Issues 記錄待辦與已知問題，展現專案管理思維。

## 專案與作品的方向

專案的核心驅動力應源於你自己的觀察與好奇心，目標是「解決某一問題」，而非完成課堂作業。常見的高中生專案原型：

- **個人網站/作品集** — 經典起點，可作為展示其他專案的平台。
- **資料視覺化與分析** — 取用政府開放資料（交通流量、空氣品質），用 Python（Pandas、Matplotlib）或 JavaScript（D3.js）轉化為圖表並撰寫分析報告。
- **網頁應用程式/服務** — 為校園或社群的實際問題打造工具，如社團活動管理系統、讀書會媒合平台。
- **AI/ML 探索（2026 趨勢）** — 串接大型語言模型 API、運用 RAG 打造能回答特定主題的問答工具，或設計簡單的 AI Agent。重點是能說明背後原理與限制（模型為何產生幻覺、RAG 如何改善正確性），並誠實標註哪些部分借助了 AI 工具。
- **演算法/系統實作** — 親手實現複雜資料結構或演算法、建立簡單模擬器，強烈展現對理論的理解（C++ 為主）。

## 展現社群參與

- **技術部落格** — 在 Medium、HackMD 或個人網站記錄專案開發日誌、學習筆記、技術觀念釐清。持續更新的部落格是證明自主學習熱情與書面溝通能力最有力的證據。
- **開源貢獻** — 不一定要寫核心程式碼。翻譯文件、完善過時說明、提交清晰可重現的 Bug Report，都是受社群重視的協作能力。
- **學生計算機年會（SITCON）** — 完全由學生自發籌辦的年度技術研討會（2026 年於 3 月 28 日在中央研究院舉行，主題「Jam the Chaos」）。從「會眾」到「志工」再到「閃電講講者」，參與層次越深，越能證明你已融入本地科技社群。議程徵稿與索票時程通常於前一年秋冬至當年初開放，建議及早關注官網。

## 多元表現地雷

- **「獎盃陳列室」式檔案** — 只羅列獎項證書，卻沒有串連它們的故事。
- **昂貴的被動式營隊** — 葉丙成教授明確指出，純粹花錢參加營隊並不會讓教授加分，除非它是你真誠探索科系的一環。這類活動常被視為「資訊的被動消費者」。
- **未經整理的課堂作業堆砌** — 一堆未註解、無反思的程式碼，反而稀釋了重點。
- **重量不重質** — 提交十個複製貼上、自己卻說不出所以然的專案，不如一個有完整「動機 → 過程 → 反思」紀錄的小專案。

**黃金法則：一個有完整紀錄的真實專案，其價值遠勝過十個只有華麗成果截圖的半成品。**
