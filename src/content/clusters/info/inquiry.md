## 怎麼選題

成大資工智慧系統實作組對專案的要求是以解決某一個問題為目標，修課作業或解題練習不算。拿這條當選題標準，可以照四步做：

1. 找問題：從生活裡找一件可以用程式改善的麻煩事，例如社團開會時間總是喬不攏。
2. 想做法：想一個自己做得出來的解法，例如做一個讓社員填可以開會時段的網頁。
3. 動手做：把想法寫成程式，先做出能用的基本版本。
4. 檢討再改：請會用到的人試用，記下哪裡不好用，再改一版。

題目大小不重要，從找問題到改版的過程完整比較重要。題目從自己好奇或覺得麻煩的事出發，寫的時候有話可寫，面試被問也講得出來。

## 可以做的方向

- 資料分析與視覺化：拿政府開放資料，例如交通流量、空氣品質，用 Python 整理、分析，做成圖表或網頁儀表板，寫出你看到什麼。
- 校園或社群工具：替學校、社團的實際問題做網頁或小程式，例如社團活動報名、讀書會配對。
- AI 應用：把現成的模型用在自己蒐集的資料上，或串接大型語言模型的 API，做一個回答特定主題的問答工具。要說得出它的原理和限制，例如模型為什麼會答錯。金鑰不要放進公開的程式碼，做法見〈多元表現亮點策略〉。
- 演算法或系統實作：從課本挑一個資料結構或演算法自己寫出來，比較不同寫法的速度，或做一個簡單的模擬器，例如交通流量模擬。
- 物聯網：用 Arduino 或 Raspberry Pi 做一個會和現實互動的裝置，例如自動澆水、記錄教室溫溼度。

## 用什麼語言

| 語言 | 常見的專案 | 對應的大學領域 |
| :---- | :---- | :---- |
| Python | 資料分析與視覺化、機器學習、串接大型語言模型 API、網路爬蟲 | 資工的人工智慧、資料科學；資管的商業智慧、資料探勘 |
| C++ | 演算法實作與速度比較、小型遊戲、物理模擬 | 資工的資料結構、演算法、作業系統 |
| JavaScript | 互動網頁、作品集網站、線上工具、資料視覺化網頁 | 資工的軟體工程、網路程式設計；資管的電子商務、人機互動 |

第一個專案不知道選哪個，可以先學 Python，入門教材和現成的套件都好找。APCS（大學程式設計先修檢測）的程式識讀可以選 C 或 Python 題本。

用 AI 幫忙寫程式沒關係，但要能說明這段程式為什麼這樣寫、你怎麼找出它的錯。

## 計畫怎麼寫、怎麼記錄

親子天下的整理寫，自主學習計畫沒有規定格式，寫清楚學習主題、目標、內容、時數和方法就可以。計畫失敗也可以寫，說清楚從中看出哪些問題、怎麼改進，「就是一個完整的自主學習歷程了」。

- 主題和目標：寫清楚想解決什麼問題、想學會什麼，例如「學會用 Python 讀開放資料，做出學校附近的空氣品質圖表」。
- 每週進度：列出每週要學的內容、參考資料和實作步驟。
- 過程紀錄：遇到的錯誤、怎麼查、怎麼解決，都記下來。筆記可以寫在 HackMD，程式碼放 GitHub，每做完一小段就 commit 一次。
- 成果和反思：最後寫做出了什麼、哪裡沒做到、下次會怎麼改。

整理好的計畫和紀錄，可以當多元表現的「高中自主學習計畫與成果」交。做完也可以寫成部落格文章，或投稿到學生計算機年會（SITCON）分享。GitHub 怎麼經營見〈多元表現亮點策略〉，高一到高三的時程見〈申請備審與面試要點〉。

## 各學類的體驗建議

ColleGo! 每個學類頁都列了高中可以做的「學類體驗」，下表各摘一兩項。

| 學類 | ColleGo! 建議的體驗 |
| :---- | :---- |
| 資訊工程 | 選一個數學專題挑戰，例如數學遊戲或數學難題；課堂上遇到科學或程式設計專題的困難，先用學過的知識分析原因（經營 GitHub 的建議見〈多元表現亮點策略〉） |
| 資訊管理 | 分析生活中遇到的問題，試著有組織地解決；閱讀原文書、英文新聞這類科技英文資料 |
| 數據統計 | 用統計概念想自己關心的事，例如什麼時間去便利商店才不會遇到人潮 |
| 生物資訊 | 修校內資訊選修課，試著用程式整合、分析資料，整理成觀察筆記 |
| 資訊傳播 | 開網頁放自己的作品，或拍影片上傳影音平台，和網友互動 |
| 媒體設計 | 把生活觀察剪成特定議題的短影音，傳播後觀察成效 |
| 圖書資訊 | 把家裡的刊物、收藏品分門別類，依分類架構給每一件編號 |
| 數位學習 | 用網頁、應用程式、電子書、線上影片學習，分析優缺點並提出改善方向 |
